$ARGUMENTS 주차를 통합 분석하고, 그 결과를 바탕으로 스킬 제안과 AAA 봇 인사이트까지 업데이트해줘.

## 실행 절차

### 1. 데이터 수집
- `00_missions/Week_0${ARGUMENTS}_submit/` 의 모든 멤버 파일 읽기
- `02_skill&insight/` 의 모든 파일 읽기
- `01_meetings/Week_0${ARGUMENTS}_weekly.md` 회의록 읽기 (해당 주차 과제 피드백 포함)
  - 해당 파일이 없으면 건너뛰기
- `90_analysis/members/` 의 모든 멤버 프로필 읽기 (멤버별 next step 도출에 사용)
- `91_proposals/스킬_제안.md`, `91_proposals/AAA_봇_인사이트.md` 기존 내용 확인 (중복 방지, 누적 업데이트)
- 파일 크기 10바이트 이하인 파일은 미제출로 간주하고 건너뛰기

### 2. 인사이트 중심 분석 리포트 작성

`90_analysis/weekly/Week_0$ARGUMENTS_분석.md` 파일을 아래 형식으로 생성:

```markdown
---
week: N
date: 오늘날짜
tags:
  - 주차분석
total_submissions: 제출인원수
---

## 이번 주 핵심 발견

**한 줄로 요약되는 이번 주의 가장 중요한 인사이트.**

핵심 발견에 대한 2~3문장 부연 설명. 왜 이것이 중요한지, 어떤 패턴이 발견되었는지.

---

## 주요 트렌드

### 1. 트렌드 제목
설명. 구체적인 사례와 숫자 포함. 닉네임 대신 "한 멤버는", "여러 멤버가" 등으로 표현.

### 2. 트렌드 제목
설명.

### 3. 트렌드 제목
설명.

---

## 이번 주 독특한 시각

### "인용할 만한 한 줄"
독특한 접근을 한 사례 설명. 다수와 다른 관점이나 창의적 시도.

---

## 이번 주 키워드

키워드1 · 키워드2 · 키워드3 · ...

---

## 다음 주에 기대되는 것

- 이번 주 트렌드가 어떻게 발전할지
- 새로운 시도 가능성
- 미해결 질문
```

### 작성 원칙
- **제출현황 테이블 금지** — 누가 제출했는지, O/X 테이블 넣지 않기
- **닉네임 직접 언급 금지** — "한 멤버는", "여러 멤버가", "과반수가" 등으로 표현
- **에디토리얼 톤** — 보고서가 아니라 매거진 기사처럼 작성
- **구체적 숫자와 사례** — "8개 채널", "하루 만에", "6개 에이전트" 등
- **핵심 발견은 한 줄** — 이번 주를 관통하는 하나의 인사이트

### 3. 현황 업데이트
- `92_status/진행현황.md` 업데이트
  - 출석/과제/벌금 현황 테이블 업데이트
  - 최근 활동 요약

### 4. 스킬 제안 도출 및 업데이트

`91_proposals/스킬_제안.md` 에 이번 주 분석에서 도출된 제안을 **누적 추가** (기존 항목은 보존).

제안 도출 기준:
- **반복 작업 패턴** — 여러 멤버가 비슷한 파이프라인을 짠 경우 공용 스킬 후보
- **공통 관심사 클러스터** — 3명 이상이 관심을 보인 주제
- **"해보고 싶은 것" 패턴** — 멤버들이 반복 언급한 실험
- **트렌드 연결** — 학습 내용과 AI/ML 트렌드 접점

제안 유형: Claude Code 스킬 / Obsidian 플러그인 / CLI 도구

각 제안에 포함: 난이도(초급/중급/고급), 관련 개념, 추천 멤버, 참고 wikilink.

### 5. AAA 봇 인사이트 업데이트

`91_proposals/AAA_봇_인사이트.md` 에 아래 섹션을 **누적 추가**:

#### 5-1. 프로젝트 아이디어
- 이번 주 과제를 조합/확장해서 만들 수 있는 프로젝트
- 멤버 간 시너지 아이디어 (A의 결과물 + B의 결과물 = ?)

#### 5-2. 이렇게 하면 더 좋겠다
- 과제 → 재사용 가능한 스킬/템플릿으로 전환할 만한 것
- 스터디 운영 개선 아이디어

#### 5-3. 멤버별 Next Step (이번 주 신규)
각 멤버 프로필(`90_analysis/members/`)과 이번 주 과제를 바탕으로 "다음에 이걸 시도해보면 어떨까"를 멤버당 1~2줄로 제안. 예:
```
- **[멤버 닉네임]**: 현재까지 [X를 하고 있음]. 다음 스텝으로 [Y 시도] — [이유/연결점]
```

#### 5-4. 아무도 시도하지 않은 영역 (이번 주 신규)
- 이번 주차에서 **공백으로 남은 주제/기술/도메인** 을 2~3개 짚기
- 왜 건드릴 만한지 1줄씩 설명 — 다음 주 도전 후보로 제시

#### 5-5. 자유 생각
- 이번 주 관통하는 메타 관찰 (에디토리얼 톤)

### 6. 멤버 프로필 갱신 (`90_analysis/members/*_프로필.md`)

각 멤버의 `90_analysis/members/{닉네임}_프로필.md` 파일을 갱신한다. **백필 트리거 + 증분 갱신** 두 모드로 동작.

#### 6-1. 모드 판단
각 프로필 파일의 frontmatter `last_updated` 와 `## 참여 이력` 테이블의 마지막 주차 행을 읽어 판단:

- **증분 모드**: 마지막 기록된 주차가 **이번 주차 직전 (`N-1`)** 인 경우 → 이번 주차 한 줄만 추가
- **백필 모드**: 마지막 기록된 주차가 `N-1` 보다 뒤쳐진 경우 → **빠진 주차부터 이번 주차까지 모두 채움**

#### 6-2. 갱신 내용
프로필 파일의 아래 필드를 갱신한다:

1. **frontmatter**
   - `last_updated`: 오늘 날짜
2. **`## 참여 이력` 테이블**
   - 빠진 각 주차마다 행 추가: `| Week 0N | O/X | O/X | O/X |`
   - 미션 제출 여부, 개념 작성 여부, 인사이트 작성 여부를 해당 주차 데이터로 채움
3. **`## 관심 키워드`**
   - 기존 키워드 보존하되, 새 주차에서 등장한 **새 키워드 2~3개만** 누적 추가 (중복 제거)
4. **`## Week 0N 요약`** (주차별 섹션, 누락된 주차마다 신규 섹션 추가)
   - 해당 주차 과제에서 도출된 3~5줄의 핵심 활동 요약
   - Obsidian wikilink 사용 (`[[Week_0N_개념이름]]`)
   - 에디토리얼 톤 금지 — 사실 나열 중심

#### 6-3. 미제출 멤버 처리
이번 주차에 미제출인 경우:
- 참여 이력 테이블에는 `| Week 0N | X | X | X |` 행만 추가
- `Week 0N 요약` 섹션은 **생성하지 않음** (백필 포함)

#### 6-4. 제외 멤버
`99_meta/멤버목록.md` 기준 현재 활성 멤버만 대상. 삭제된 멤버 프로필은 생성/갱신하지 않는다.

### 7. 제안 파일 frontmatter 갱신

두 제안 파일(`스킬_제안.md`, `AAA_봇_인사이트.md`)의 frontmatter를 아래 필드로 갱신:

```yaml
---
tags:
  - 제안
  - (스킬 or 인사이트)
last_updated: 오늘날짜
count: 총 항목 수
preview: "한 줄 요약 (홈페이지 카드에 노출됨, 60자 이내)"
highlights:
  - "최신 항목 제목 1"
  - "최신 항목 제목 2"
  - "최신 항목 제목 3"
---
```

`highlights`는 **이번 주차에 추가한 신규 항목 상위 3개의 제목**으로 갱신. 홈페이지 `/analysis` 하단 "다음에 만들어볼 것들" 카드가 이 필드를 읽어 preview를 렌더링한다.

### 작성 원칙
- 실현 가능한 것 위주, 1~2주 단위 스코프
- 한국어, Obsidian wikilink 활용 (`[[Week_0N_멤버]]`)
- 기존 제안은 보존하고 **누적**으로 추가 (제안 번호는 이어서)
- 모든 파일은 Obsidian 마크다운 형식
